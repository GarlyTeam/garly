# Security Policy

## Reporting a vulnerability

The security and privacy of Garly users are taken seriously.

Please do not report security vulnerabilities through public GitHub issues, discussions or social media.

Use GitHub's private vulnerability reporting feature:

1. Open the **Security** section of this repository.
2. Select **Report a vulnerability**.
3. Describe the issue, the affected component and the steps required to reproduce it.

If possible, include screenshots, logs with personal information removed and a suggested mitigation.

## Responsible testing

When investigating a potential vulnerability:

- Use only accounts and data that belong to you.
- Do not access, modify or delete another user's information.
- Do not perform denial-of-service or automated high-volume testing.
- Do not attempt social engineering.
- Do not publicly disclose the issue before it has been investigated and addressed.

## Scope

Reports may concern the reviewed public components, authentication, account isolation, privacy controls, Android and iOS safety functionality and Garly-operated services.

Third-party platforms and services should normally be reported directly to their respective providers.

## Supported versions

Garly is available on iOS and Android. Only the most recent publicly available app versions are actively supported. The native source directories in this repository are earlier reviewed snapshots, not guaranteed copies of the latest store builds.

## Safety notice

A security report should never be used to trigger, delay or interfere with real emergency communications.
